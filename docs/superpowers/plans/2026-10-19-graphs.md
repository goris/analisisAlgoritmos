> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a `graphs/` Go exercise that finds the connected components of `Grafo_no_conexo.txt`
with recursive DFS, and the minimum route 0→14 in the digraph `Grafo_ponderado.txt` with Dijkstra.

**Architecture:** `package main` with four focused files:
- `graph.go`: adjacency-list graph and a single parser for both input formats.
- `dfs.go`: CLRS `DFS` / `DFS-VISIT` for the connected components.
- `dijkstra.go`: Dijkstra over a `container/heap` min-heap with lazy deletion, plus path reconstruction.
- `main.go`: embeds `data/*.txt` with `go:embed` and prints both answers in Spanish.

**Tech Stack:** Go 1.27, standard library only: `embed`, `regexp`, `strconv`, `container/heap`, `math`, `slices`, `testing`.

**Spec:** `docs/superpowers/specs/2026-10-19-graphs-design.md`

## Review Focus

1. **CRLF line endings.** The real files use `\r\n`. The parser must treat them like `\n`. Pinned in Task 1 (`crlf line endings`).
2. **Zero-weight edge.** It is non-negative, so it must be accepted, not rejected. Pinned in Task 1 (`zero weight accepted`) and Task 3 (`zero weight edge`).
3. **Parallel edges with different weights.** Dijkstra must use the cheaper one. Pinned in Task 3 (`parallel edges uses cheaper`).
4. **`Nodes` listed out of order vs. duplicated.**
   - Out of order is still exactly `{0..n-1}`, so it is accepted.
   - A duplicate is rejected.

   Pinned in Task 1 (`nodes out of order`, `duplicate node`).
5. **An empty edge list `[]`.** The result is a valid graph of isolated vertices, each its own component. Pinned in Task 1 (`empty edge list`) and Task 2 (`isolated vertices`).

- [ ] **Step 4: Implement the graph type, `parseGraph` and `loadGraph` in `graphs/graph.go`, plus the embed stub in `graphs/main.go`**

How `parseGraph` works:
1. **Split the text.** Use `strings.Index` on `"Nodes:"` and `"Edges:"`. If either is missing, return an error.
2. **Read the vertices.** Every `\d+` between the two markers is a vertex label. Sort the labels; the result must equal `0..n-1`. That rejects gaps and duplicates, and allows any order.
3. **Read the edges.** Match every edge tuple after `Edges:` with
   `\(\s*(\d+)\s*,\s*(\d+)\s*(?:,\s*\{\s*'weight'\s*:\s*(-?\d+)\s*\})?\s*\)`.
   - If the weight group is missing, the weight is 1.
   - A weight below 0 is an error.
   - An endpoint `>= n` is an error.
   - Append `u→v`. When undirected, also append `v→u`.
4. **Line endings.** `\s` already matches `\r`, so CRLF needs no special handling.

### Task 3: Dijkstra and path reconstruction

**Files:**
- Create: `graphs/dijkstra.go`
- Test: `graphs/dijkstra_test.go`

**Interfaces:**
- Consumes: `graph`, `parseGraph`, `loadGraph` (Task 1)
- Produces:
  - `type pqItem struct { vertex, dist int }` and `type priorityQueue []pqItem`, which implements `heap.Interface` (`Len`, `Less` by `dist`, `Swap`, `Push(any)`, `Pop() any`)
  - `func dijkstra(g *graph, source int) (dist []int, prev []int)`. Unreachable means `dist[v] == math.MaxInt` and `prev[v] == -1`. `prev[source] == -1`.
  - `func shortestPath(prev []int, source, target int) []int`. Returns `[source]` when `target == source`, `nil` when `target` is unreachable (`prev[target] == -1`), and otherwise the vertices from `source` to `target`.

- [ ] **Step 3: Implement `priorityQueue`, `dijkstra` and `shortestPath` in `graphs/dijkstra.go`**

**Initialization:**
- `dist` is all `math.MaxInt` and `prev` is all `-1`.
- `dist[source] = 0`, then `heap.Push(pq, pqItem{source, 0})`.

**Main loop:**
- Pop. If the vertex is already `visited`, skip it: that is the lazy deletion. Otherwise mark it visited.
- For each edge `e`: if `!visited[e.to] && dist[u]+e.weight < dist[e.to]`, update `dist` and `prev` and push a new item.
- The relaxation must use strict `<`.

**`shortestPath`:** walk `prev` from `target` back to `source`, then `slices.Reverse`.
